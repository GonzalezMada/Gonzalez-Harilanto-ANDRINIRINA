# Quickstart: Validating the Bilingual Portfolio Site

This is a run/validation guide, not an implementation guide — it proves the feature works
end-to-end once built. See [data-model.md](./data-model.md) and [contracts/](./contracts/) for the
shapes being validated, and `tasks.md` (generated by `/speckit-tasks`) for build steps.

## Prerequisites

- Node.js (LTS) and a package manager installed.
- Dependencies installed: `npm install`.
- Content present: at least one entry in each of `projects`, `blog`, `leadership` for both `fr`
  and `en`, plus `public/cv/cv-fr.pdf`, `public/cv/cv-en.pdf`, and the professional photo asset.

## 1. Type & content-schema validation

```bash
npm run typecheck   # tsc --noEmit + astro check
```

**Expected**: passes with zero errors. A missing/malformed frontmatter field in any content file
(e.g., a Project missing `externalLink`) MUST fail this step — confirms the
[content-collections contract](./contracts/content-collections.md) is enforced.

## 2. Content-lint (bilingual parity + category consistency)

```bash
npm run lint:content   # translationKey coverage FR<->EN, category consistency, i18n dictionary key parity
```

**Expected**: passes. Temporarily remove the EN counterpart of an FR blog post's
`translationKey` and re-run — this step MUST fail, confirming spec FR-018 (content parity) is
enforced automatically rather than relying on manual review.

## 3. Unit / component tests

```bash
npm run test:unit   # Vitest + Testing Library
```

**Expected**: all component logic tests pass (e.g., Projects filter narrows results correctly,
language-switch link resolution picks the right counterpart per the
[routing contract](./contracts/routing.md)).

## 4. Build

```bash
npm run build   # astro build
```

**Expected**: static output produced with no errors; both `/fr/` and `/en/` route trees present
in the output per [contracts/routing.md](./contracts/routing.md).

## 5. End-to-end + visual regression tests

```bash
npm run preview &            # serve the built output
npm run test:e2e             # Playwright: e2e/ + visual/
```

**Expected scenarios covered** (map to spec User Stories):

- **US1 (Home)**: photo and exactly 3 facets render; each facet link navigates to its section.
- **US2 (Language switch)**: switching language on Projects/Blog/Leadership/Home lands on the
  equivalent content, not the Home page (spec SC-002).
- **US3 (CV download)**: CV download control on any page downloads the PDF matching the active
  locale.
- **US4 (Projects filter)**: selecting a category shows only matching cards; clearing restores
  the full list; a filter with no matches shows the empty-result state.
- **US5 (Leadership)**: all four named entries (YALI RLC SA, Fablab EnR-out, Technovation Girls,
  STEM for Good) are present.
- **US6 (Blog)**: list shows title/date/summary/tags; opening an article reaches its own page with
  full content.
- **Accessibility**: `@axe-core/playwright` scan on each page/locale reports zero
  critical/serious violations (Principle IV, WCAG AA).
- **Visual regression**: screenshot comparison per page × locale matches the committed baseline
  (Principle VI, design consistency).

## 6. Performance/Accessibility/SEO gate

```bash
npm run build
npx lhci autorun   # Lighthouse CI against the built static output
```

**Expected**: Performance, Accessibility, and SEO categories each score ≥ 90 on every page
(Principle III / constitution). A regression below 90 on any page MUST fail this step.

## 7. Full pipeline (what CI runs)

```bash
npm run lint && npm run typecheck && npm run lint:content \
  && npm run test:unit && npm run build \
  && npm run test:e2e && npx lhci autorun
```

**Expected**: all steps pass before a merge to the default branch is allowed to deploy, per the
constitution's Deployment & Delivery section.
